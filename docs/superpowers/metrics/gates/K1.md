# K1

The checkpoint before `pcee-engine` (stage 3), from the registry spec §6. Over at least 4 specs that ran with
manifests, the median recall on files that existed when the plan was written must be at least 0.9; the
append-aware parallelism on verified appends must be at least 1.5; and the manifest tokens must be at most
10% of all tokens. With 4 specs, parallelism can only be 4, 2, 1.33 or 1, so the gate passes on waves only
when the four specs fit in two append-aware waves; the gate prints the wave count beside the ratio. It is
`too early` until the batch's analysis line has `appends_verified` true, that is until `registry report` has
run after the batch's specs.

```json:gate
{"id": "K1", "min_specs": 4, "where": {"has": "refreshes"}, "conditions": [
  {"metric": "manifest.recall_existing", "agg": "median", "min": 0.9},
  {"metric": "analysis.parallelism", "agg": "last", "min": 1.5, "where": {"appends_verified": true}},
  {"metric": "manifest_tokens/tokens.total", "agg": "ratio_of_sums", "max": 0.10}]}
```
