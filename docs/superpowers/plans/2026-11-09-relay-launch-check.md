# Relay Launch Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A handoff relay either lands a running lead in the project's main checkout or fails loudly with the pane's text. It never silently leaves a dead shell that the user has to `cd ~` out of.

**Architecture:** `board/relay.py` types `cd -- <root> && <claude-orchestrator> '<prompt>'` instead of the bare launcher. After typing it, relay polls the pane until its foreground is not a shell on two polls in a row (30 s cap), retries once, and otherwise raises with the captured pane text. `tmux-ctl _relay_failed` shows relay.py's own `manual:` line, so the hand-start command also cds. A frontier task reproduces the real failure to name its root cause.

**Tech Stack:** Python 3 (board/, unittest), zsh (bin/tmux-ctl, tools/tests harness), tmux 3.8.

**Spec:** `docs/superpowers/specs/2026-11-09-relay-launch-check-design.md`

## Global Constraints

- The launch line is exactly `cd -- <shlex-quoted root> && <shlex-quoted claude-orchestrator path>[ <shlex-quoted prompt>]`. No silent fallback to `$HOME` anywhere in relay.
- "Started" means `paneclass.pane_status(...)[0] != "shell"` on two polls in a row, 2 s apart, cap `START_CAP = 30.0` s. Never test for the name `claude`: tmux reports a running claude as its version binary (probed: `2.1.321`).
- Two attempts at most. Lineage (`tc_env.lineage_dir()/<session>.jsonl`) is written only after a verified start.
- relay.py's failure stderr: first line `relay failed: <reason>`, then `Start the new lead by hand in the claude window:`, then `manual: <command>`. Pane text lines in the log are prefixed `| `.
- User rule: never run the full suites; only the targeted tests named in each task.
- Scratch tmux servers start with `-f /dev/null`. Never kill processes by name or pattern; kill by PID only.
- No pushes.

The patch adds to relay.py (shown here for review; the patch is the source):

```python
START_CAP = 30.0   # seconds a relayed lead has to start before the attempt counts as failed


def launch_line(root, prompt=None):
    cmd = shlex.quote(orchestrator()) + (f" {shlex.quote(prompt)}" if prompt else "")
    return f"cd -- {shlex.quote(root)} && {cmd}"


def wait_started(tmux, pane, poll=2.0, cap=START_CAP, sleep=time.sleep, clock=time.monotonic):
    deadline = clock() + cap
    streak = 0
    while True:
        sleep(poll)
        kind, _ = paneclass.pane_status(tmux, pane)
        streak = streak + 1 if kind != "shell" else 0
        if streak >= 2:
            return True
        if clock() >= deadline:
            return False
```

and in `relay()`: `root = session_root(...)`, then `for n in range(1, attempts + 1): respawn(...); if wait_started(...): break; shown = pane_tail(...); print("relay: attempt n …", file=sys.stderr)`, with `else: raise RuntimeError(f"the new lead did not start in {root} after {attempts} attempts; the pane shows:\n{shown}")`. `main()` gains a hidden `--start-cap` test knob and the `manual:` line.
