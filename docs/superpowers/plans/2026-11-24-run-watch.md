# Run watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lead that writes a handoff doc arms the Stop guard by itself; in queue mode the board alerts on a run past its cap in a teammate's pane and, when its CPU time stops moving, kills it by PID, tells the teammate and the lead, and logs the kill for the morning report; `test_teammate_hooks.zsh` passes whatever `AGENT_BOARD_LEAD` the calling shell has.

**Architecture:** Part a is a new PostToolUse hook (`claude/plugin/scripts/handoff-arm.sh`) that creates the mark `tmux-ctl handoff-mark` creates. Part b extends what night-watch builds: `board/overview.py` samples `ps` once per overview and lists each `✦` pane's runs (`runs` record field, queue mode only); `board/watch.py` keeps a per-run state machine (alert, CPU progress, kill, teammate line, lead nudge, KILL escalation) in `watch.json` under `runs` and appends kills to `watch/kills.jsonl`; `board/server.py` wires the `ps` sampler and the teammate line. Part c is a one-line scrub in a test.

**Tech Stack:** zsh hooks and the `tools/tests/lib.zsh` harness (scratch tmux 3.8 server, `-f /dev/null`), Python 3 standard library (`board/`, `unittest`), `jq`, `cc` (a compiled stand-in for `claude` in the e2e).

## Global Constraints

- **Stacked on night-watch.** The lead rebases this branch onto night-watch's finished branch before running it; every task may assume night-watch's seven tasks are done. Each edit below is a diff against night-watch's code as its plan writes it (the planner applied night-watch's plan to a scratch clone and ran every snippet here against it). If a night-watch review moved the context, make the same change by hand.
- **Queue mode** is night-watch's: a record's `queue` field (`overview.queue_mode`). Outside queue mode the run watch samples nothing and does nothing.
- **Constants (exact):** `watch.FLAT_KILL = 2` (CPU time unchanged on 2 overviews in a row after the first sight), `watch.KILL_GRACE_S = 10`, `watch.DEFAULT_CAPS` = the spec's caps (`default_s` 900; `node --test` 360, `npm test` 360, `unittest discover -s board/tests` 1080, `tools/tests/all.zsh` 1620, `tools/tests/run-all.zsh` 1620). A run is past its cap when `elapsed_s > cap_s`; CPU "rose" when strictly greater. First `match` substring wins, no match → `default_s`.
- **Texts (exact):**
  - alert (feed line `<project>: <text>`, kind `run_overdue`, tier `critical`): `<name> run past cap: <cmd, 80 chars> (<n> min, cap <c> min)`
  - teammate pane: `[Watch] killed <cmd, 80 chars> after <n> min, no progress: report to the lead`
  - lead nudge: `[Watch] killed <name>'s <cmd, 80 chars> after <n> min, no progress: read its report.`
  - `<name>` is the window name without `✦ `; `<cmd>` is the command line with whitespace runs collapsed (`notify.flat_cmd`); `<n>` = `elapsed_s // 60`, `<c>` = `cap_s // 60`.
- **Files:** `$TC_STATE_DIR/watch.json` = `{"stalls": {…night watch…}, "runs": {"<window>:<pid>": {"project", "first_at", "cpu", "flat_count", "killed_at", "cap_s", "cmd"} + after the kill {"pids", "escalated", "told", "nudged_at", "min", "window"}}}`; `$TC_STATE_DIR/watch/kills.jsonl`, one line per kill: `{"at", "project", "window", "pid", "cmd", "elapsed_s", "cap_s"}`. The handoff mark is `$TC_STATE_DIR/handoff-pending/<session id>`, the file `tmux-ctl handoff-mark` writes.
- **Kill by PID only** (`os.kill`), never a pattern (`pkill`, `pgrep | xargs kill`). Unit tests never signal a real process (an injected `kill`); the e2e signals only the `perl` it started.
- **Isolation:** every test sets `TC_STATE` to a temp dir; `test_handoff_arm.zsh` sets `TC_HANDOFFS_DIR` and `HOME` (for the default dirs) to temp dirs. Leak checks: the real `handoff-pending` dirs and the real `watch*` files never name a test's session or project.
- Commits: conventional with scope (`fix(tests): …`, `feat(plugin): …`, `feat(board): …`, `test(board): …`, `docs(architecture): …`), path-scoped (`git commit -- <paths>`), ending with the attribution trailer your harness specifies.

**User decisions (already made):**
- One spec, three parts (a, b, c); each has its own tests (spec Decision 1).
- Hung runs: the night watch detects and acts, not a worker.md rule alone (Decision 2).
- The handoff guard arms itself when a lead writes a handoff doc (Decision 3).

**Planner assumptions (made without the user; the lead may override):**
- A1. Lead nudge: night-watch's mechanism, its `nudge(project, line)` seam (the board's `COMMENTS` queue, the `[Board]` line path), called only while `_lead_ready(rec)`. Teammate line: `tmux-ctl tell` refuses a `✦` teammate window (it needs `@tc_agent`, `bin/tmux-ctl` `is_agent`) and the `COMMENTS` queue delivers only to the `claude` window, so the board types it directly: `server.tell_pane(pane, line)` = `send_line` (the sender `deliver_comments` uses: `send-keys -l`, then Enter), held while `_input_busy(pane)`, and called only while the teammate's `agents[]` state is `ready` or `working` (not `waiting`, a prompt for the user). This replaces the spec's "through tmux-ctl".
- A2. The `run_overdue` alert is sent by `board/watch.py` itself (`Watch._alert(..., kind="run_overdue", key="<window>:<pid>")`), not as a notifier condition: the notifier allows one event per kind per project every `RATE_S` (300 s) and marks a suppressed condition active, so a second overdue run in the same project would never be alerted. `notify.py` carries the kind (`KINDS`), the text (`run_overdue_text`, `flat_cmd`); `discord_feed.NOTIFY_TIERS["run_overdue"] = "critical"`.
- A3. What a run is (the spec's "descendants … excluding the claude process itself and shells whose only child is watched", made precise). Probe, 2026-11-24, this machine: a teammate pane's process is the claude binary itself (`/Users/…/.local/share/claude/versions/2.1.331 --agent-id … --agent-name …`, parent the tmux server); its direct children include `caffeinate -i -t 300` and MCP servers (`node …/discord-mcp-stub.js`), alive as long as the session with flat CPU, and each Bash tool call is a child `/bin/zsh -c source …/shell-snapshots/snapshot-zsh-….sh … eval '<cmd>'`. Watching every descendant would kill the MCP servers after 15 min. So (`overview.run_roots`): under a claude process only shell children are followed; a shell with exactly one child stands for that child; a shell with no child (an idle prompt) is never a run; the first other process is the run. Its CPU time is its whole subtree's, so `npm test` whose `node --test` child works is "moving". The e2e's real-state check ran on 9 claude processes with 11 non-shell children: 0 counted as runs.
- A4. The kill: TERM to the run's PID, then to each descendant in the same overview's sample, all by PID; the KILL to those still alive (`kill(pid, 0)` probe first) is sent on the first overview at least `KILL_GRACE_S` after the TERM, not from a timer thread (night-watch: no timer in the board), so it lands 10–20 s after the TERM. If the run's PID is gone at the TERM (`ProcessLookupError`), the entry is dropped: the stall clears, nothing is logged.
- A5. `handoff-arm.sh` and teammates: a teammate inherits `AGENT_BOARD_LEAD=1` from the lead (it is set in this planner's own teammate shell), so the hook also exits when the Claude process args hold `--agent-name` (the test `teammate-remind.sh` uses, with its `TC_TEAMMATE_ARGS_FILE` seam).
- A6. Part c's last step (remove the shared-context gotcha) is the lead's: the shared context is curated by the lead and `tmux-ctl context` has no remove command. Task 1's implementer reports `Context learned: remove the gotcha "test_teammate_hooks.zsh fails on main whenever AGENT_BOARD_LEAD is set …"; the test now scrubs it`.
- A7. `ps` argv: `ps -ax -ww -o pid=,ppid=,etime=,time=,command=` (`=` drops the header, `-ww` the width limit). Probe: 855 lines in 0.07 s; macOS prints `time` as `mmm:ss.cc` past an hour (`1389:17.59`) and `etime` as `dd-hh:mm:ss`; `overview._dur` reads both and Linux's `[dd-]hh:mm:ss`.
- A8. The caps file is the board checkout's own `docs/superpowers/run-caps.json` (`watch.CAPS_FILE`), overridden by `TC_RUN_CAPS` (tests, e2e). It is read when a run is first checked against its cap, so an edit takes effect on the next new run. A missing or unparsable file logs one line per file and error kind.
- A9. The e2e's teammate is a compiled stand-in named `claude` that runs `perl -e "sleep 9999"` through `/bin/zsh -c` (as a Bash tool call does), not a window running perl directly: the pane then stays a claude pane after the kill, so the typed line can be seen, and the run is found by the same rule as in production.
- A10. `overview.RECORD_KEYS` gains `runs` between `pace` and `agents` (the existing tests want `agents` last); night-watch's `RecordKeysTest` changes from `[-5:]` to `[-6:]`.
- Known limit (spec scope): a teammate's background server started by a Bash call (`run_in_background`) is a run too, killed after `default_s` with flat CPU in queue mode.
