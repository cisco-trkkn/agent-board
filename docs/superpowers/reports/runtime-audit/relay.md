## Orchestrator cost

**Metric semantics.** `orchestrator_share` = main tokens / all tokens in the same session file (`session_metrics.py` docstring). Teammates live in their own session files, so for an agent-team session the metric only sees the lead's one-shot subagents. **Derived join for the traced task.** Lead `48822fd2` + its 13 subagents + the four teammates it spawned (matched by `name` in the lead's Agent calls = `agentName` in the teammate transcript, same hour, same project dir): main 37,677,609 tokens (41.4%), subagents 2,035,834 (2.2%), teammates 51,249,329 (56.3%), total 90,962,772. Output tokens: main 97,994 = 15.6% of 629,778. The in-session `orchestrator_share` for the same session is 0.949. **The in-session metric overstates the lead by ~2.3× for team sessions.**

**Window-wide by agent kind** (`totals.by_agent_kind`, no join needed): main 1,619,134,637 tokens (60.2%) of which 98.4% cache reads, output 4,776,739 (38.4%); team 975,029,421 (36.2%), output 6,979,027 (56.1%); sub 96,389,452 (3.6%). The lead's bill is reading, not thinking.

**What the lead decided for that cost** (`48822fd2`): tier and role per task (all matched the plan); combining spec and code-quality review into one sonnet reviewer per task; triaging 6 review reports and issuing 6 fix briefs; correcting the one blocked dispatch; accepting a user side-request (`citree`) mid-plan and brief-ing it in 5,629 chars; 24 rulings over the plan (per the handoff doc); shutting teammates down when done (4 shutdown requests, median 0.4 s idle tail); handing off within 90 s of the first warning. Nothing here is a routine decision that a rule could have made cheaper except the shutdown confirmations and hand-back acknowledgements, which still cost a full-context turn each.

**H2 verdict.** Routing, spawning and decomposition are already deterministic where they can be: plan tiers, gate enforcement, SDD scripts for briefs and review packages. The Opus lead's reasoning is not the expensive part; its turn count is. Replacing the model would save little; reducing agent-triggered turns (batching hand-backs, letting teammates report once) would.

Teammate peak context median 97,226, p90 218,707, 13 of 286 ≥ 300K.

**Overlap in the traced task (from timestamps).** `icons`∥`inventory` 11:25–11:32 (7 min); `edges`∥`grammar` 11:36–11:50 (14 min of a 102-min session); `e2e`∥`citree` 13:02–13:11 (9 min); `tracer`∥`e2e#2` 13:18–13:40 (17 min); `finalrev`∥`wave` 13:59–14:07. **Verdict (H6).** Parallel teammates paid off when the plan had disjoint branches (T6 alongside T3–T5 saved ~14 min) and for independent reviewer dispatches; duplicate research is negligible (0 repeat reads in the four teammates). It did not pay for review loops, which are serial by nature, and the lead's cost scales with the number of agent messages rather than the number of agents. Four dead spawns and one double dispatch show the spawn path is not yet reliable; `orchestrator.md:15-16` makes the lead check `pane_dead` by hand.

## Handoff and recovery

**How the trigger is measured.** `claude/hooks/context-size-guard.sh` (registered as UserPromptSubmit in `~/.claude/settings.json`) reads the session's own transcript: `tail -n 400`, the last non-sidechain assistant line's `input + cache_read + cache_creation` (`:10-14`). That is **native, exact usage of the previous request**, not an estimate; the threshold is `CLAUDE_CONTEXT_WARN_TOKENS`, default 300,000 (`:4`). It is a **warning, not a limit**: it injects a system message and `additionalContext` telling the model to recommend `/handoff` (`:19-21`) and never blocks. It fires only on human prompts: in `48822fd2` the lead sat at ≥300K from 13:01:37 while handling 10 agent-triggered turns and saw its first warning at the next human prompt, 13:12:00. Teammates receive only `teammate-message`s, so `grammar` (474K) and `e2e` (498K) logged zero warnings. Autocompact is on (`settings.json:190 autoCompactEnabled: true`) but **zero compactions** were detected in the window (`handoff_trace.json compactions: []`), with main contexts reaching 666,520 (`50668da3`) and a teammate 564,638 (`f2c537a5`).

**Automatic or orchestrator-directed?** Orchestrator-directed and user-approved: `/handoff` (`claude/plugin/skills/handoff/SKILL.md`) checkpoints the team (`:12-18`), writes the doc (`:20-44`), shuts the team down (`:46-48`), asks the user (`:50-57`, "never skip"), then `tmux-ctl relay` (`:59-68`). `board/relay.py:32-42` waits until the pane reads idle on two polls 2 s apart (120 s cap), `respawn-pane -k` and starts `claude-orchestrator "Read <doc> and continue…"` (`:65-69`), appending `{ts, old_session_id, doc, pane}` to `lineage-<session>.jsonl` (`:80-82`). On failure the old pane is untouched (`:103-105`). All three `relay-*.log` files end in "relayed".

## Findings

### F-relay-1: In-session `orchestrator_share` overstates the lead's share of team work by ~2×
Label: Measured
Evidence: `session_metrics.json` `48822fd2` `orchestrator_share.value` 0.949 vs derived join (lead + 13 subagents + teammates `d34ef111`, `984afea4`, `ddd65627`, `947dde66`): main 37,677,609 / 90,962,772 = 0.414; output 97,994 / 629,778 = 0.156. Window `totals.by_agent_kind`: main 60.2% of tokens, 38.4% of output; team 36.2% / 56.1%.
Component: tools/audit/session_metrics.py (teammate sessions are separate files, `session_metrics.py` docstring last line) · Root cause: no lead↔teammate link in transcripts (`teammate-message teammate_id="team-lead"` carries no session id) · Impact: measured above; H2 cannot be answered from the metric as shipped.
Confidence: high · Candidate change: record the lead session id in each teammate's spawn (Agent prompt header or `tmux-teammate-window`), and have `session_metrics.py` join team sessions to their lead · How to validate: re-run the join for the 5 team-heavy leads and compare with the per-session value.

### F-relay-2: The 300K guard is silent for agent-driven turns and for every teammate
Label: Verified
Evidence: `~/.claude/settings.json` registers `context-size-guard.sh` on UserPromptSubmit only; lead `48822fd2` at ≥300K from 13:01:37 (301,792) with warnings only at 13:12:00, 13:13:27, 13:15:52 (the human prompts); teammates `984afea4` peak 473,995 and `ddd65627` peak 498,409 with 0 `CONTEXT AT` strings; 13 of 286 teammates ≥300K; 44 of 47 lead turns in `48822fd2` were agent-triggered.
Component: claude/hooks/context-size-guard.sh + hook registration · Root cause: teammate messages and subagent hand-backs do not raise UserPromptSubmit · Impact: unmeasured in quality terms — needs a per-turn context log for teammates; in cost terms the two Fable teammates alone processed 40.4M tokens.
Confidence: high · Candidate change: also run the check on Stop (or PostToolUse for SendMessage/Agent) and give teammates a lighter rule (checkpoint + report at N tokens) · How to validate: replay the three traced transcripts through the new hook and count warnings per agent.
