Verdict in one paragraph. **Window-wide by agent kind** (`totals.by_agent_kind`, no join needed): main 1,619,134,637 tokens (60.2%) of which 98.4% cache reads, output 4,776,739 (38.4%); team 975,029,421 (36.2%), output 6,979,027 (56.1%); sub 96,389,452 (3.6%). The lead's bill is reading, not thinking.

**What the lead decided for that cost** (`48822fd2`): tier and role per task (all matched the plan); combining spec and code-quality review into one sonnet reviewer per task; triaging 6 review reports and issuing 6 fix briefs; correcting the one blocked dispatch; accepting a user side-request (`citree`) mid-plan and brief-ing it in 5,629 chars; 24 rulings over the plan (per the handoff doc); shutting teammates down when done (4 shutdown requests, median 0.4 s idle tail); handing off within 90 s of the first warning. Nothing here is a routine decision that a rule could have made cheaper except the shutdown confirmations and hand-back acknowledgements, which still cost a full-context turn each.

**H2 verdict.** Routing, spawning and decomposition are already deterministic where they can be: plan tiers, gate enforcement, SDD scripts for briefs and review packages. The Opus lead's reasoning is not the expensive part; its turn count is. Replacing the model would save little; reducing agent-triggered turns (batching hand-backs, letting teammates report once) would.

**Verdict (H6).** Parallel teammates paid off when the plan had disjoint branches (T6 alongside T3–T5 saved ~14 min) and for independent reviewer dispatches; duplicate research is negligible (0 repeat reads in the four teammates). It did not pay for review loops, which are serial by nature, and the lead's cost scales with the number of agent messages rather than the number of agents. Four dead spawns and one double dispatch show the spawn path is not yet reliable; `orchestrator.md:15-16` makes the lead check `pane_dead` by hand.

## Handoff and recovery

**How the trigger is measured.** `claude/hooks/context-size-guard.sh` (registered as UserPromptSubmit in `~/.claude/settings.json`) reads the session's own transcript: `tail -n 400`, the last non-sidechain assistant line's `input + cache_read + cache_creation` (`:10-14`). That is **native, exact usage of the previous request**, not an estimate; the threshold is `CLAUDE_CONTEXT_WARN_TOKENS`, default 300,000 (`:4`). It is a **warning, not a limit**: it injects a system message and `additionalContext` telling the model to recommend `/handoff` (`:19-21`) and never blocks. It fires only on human prompts: in `48822fd2` the lead first reached 300K at 13:01:37 (301,792), then made 11 API requests, all at ≥300K, and received 2 incoming agent messages (teammate `citree` at 13:10:35 and 13:11:15) with no warning; the first warning came with the next human prompt at 13:12:00. Teammates receive only `teammate-message`s, so `grammar` (474K) and `e2e` (498K) logged zero warnings. Autocompact is on (`settings.json:190 autoCompactEnabled: true`) but **zero compactions** were detected in the window (`handoff_trace.json compactions: []`), with main contexts reaching 666,520 (`50668da3`) and a teammate 564,638 (`f2c537a5`).

**Automatic or orchestrator-directed?** Orchestrator-directed and user-approved: `/handoff` (`claude/plugin/skills/handoff/SKILL.md`) checkpoints the team (`:12-18`), writes the doc (`:20-44`), shuts the team down (`:46-48`), asks the user (`:50-57`, "never skip"), then `tmux-ctl relay` (`:59-68`). `board/relay.py:32-42` waits until the pane reads idle on two polls 2 s apart (120 s cap), `respawn-pane -k` and starts `claude-orchestrator "Read <doc> and continue…"` (`:65-69`), appending `{ts, old_session_id, doc, pane}` to `lineage-<session>.jsonl` (`:80-82`). On failure the old pane is untouched (`:103-105`). All three `relay-*.log` files end in "relayed".
