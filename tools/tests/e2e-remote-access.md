# e2e: remote access (Telegram channel per dev lead), run by the user

Not automated: it needs a real bot, the phone and the real `claude`. Tick each box only after you saw the stated observation. Use a throwaway project and a bot made for the test. Never paste a token into a terminal command line or a chat: pipe it from stdin.

Setup: spec `docs/superpowers/specs/2026-11-09-remote-access-design.md`; install steps in `docs/INSTALL.md` → "Remote access". Replace `<project>` with the tmux session's project name.

- [ ] **1. Create a bot and save its token.** In Telegram, BotFather → `/newbot`. In the project's session: `print -r -- "<token>" | tmux-ctl telegram token`. Expect `telegram: token saved for <project> (restart its lead to connect)`; `ls -l ~/.local/state/agent-board/telegram/<project>/.env` shows `-rw-------`; the token is not on screen.
- [ ] **2. Restart the lead and pair.** `claude-orchestrator --continue` in the lead's window. DM the bot from the phone; the bot answers with a pairing code. In the lead: `/telegram:access pair <code>`, then `/telegram:access policy allowlist`. Expect `tmux-ctl telegram status` to print `token: set`, `paired: 1 allowlisted`, `policy: allowlist`, `poller: running (pid N)`, `plugin: ok`, `bun: ok`.
- [ ] **3. A phone message reaches the lead.** Send "ping" from the phone. Expect it in the lead's session (a `<channel source="plugin:telegram:telegram" …>` message) within about 30 s through Netskope. Note the delay: ______ s.
- [ ] **4. The lead's reply arrives.** Ask on the phone: "reply with the word pong". Expect "pong" in the Telegram chat, outcome first, and no terminal-only answer.
- [ ] **5. A lead permission prompt answered by button.** From the phone ask the lead to run a command that prompts (for example "run `touch /tmp/e2e-remote-<project>`"). Expect the prompt as a message with buttons; tap Allow; expect the terminal prompt to clear and `ls /tmp/e2e-remote-<project>` to find the file. Remove it afterwards.
- [ ] **6. A teammate prompt approved with `approve n`.** Have the lead start a teammate that triggers a prompt (for example a `touch` in a worktree) and ask the lead on the phone to tell you when it waits. Expect a message with `#n`, the teammate's name, the tool and the command verbatim, and `reply "approve n" or "deny n"`. Reply `approve n`. Expect the lead's report naming the label it pressed (`Yes`) and the pane after it; in the teammate's window the prompt shows accepted once and no "always" rule appears in `.claude/settings.local.json` (`git status` clean for that file).
- [ ] **7. A vague or wrong answer does nothing.** With another teammate prompt waiting, reply "go ahead" and then `approve 99`. Expect the prompt to stay waiting in the teammate's window both times and the lead to ask again.
- [ ] **8. `deny n`.** With a waiting teammate prompt, reply `deny n`. Expect the pressed label `No` in the lead's report and the teammate's command not run.
- [ ] **9. A second project's bot stays separate.** Repeat steps 1–2 for a second project with its own bot. Expect each `tmux-ctl telegram status` to show its own `poller: running (pid N)` with different pids, and a message to bot A to reach only project A's lead.
- [ ] **10. `status` never shows the token.** `tmux-ctl telegram status` in each project, then `tmux-ctl telegram status 2>&1 | grep -c "<the digits before the colon of the token>"`. Expect `0`. Also `tmux-ctl telegram forget` in the throwaway project prints `telegram: token removed for <project>` and `access.json` is still there (`ls ~/.local/state/agent-board/telegram/<project>/`).
- [ ] **11. (a) A relay keeps its prompt on a Telegram lead.** From the Telegram lead run `tmux-ctl relay <doc>` with a handoff doc. Expect the fresh lead's window to start with `--channels plugin:telegram@claude-plugins-official` (`ps -o args= -p <claude pid>`) and the handoff prompt to arrive intact as its first message (not swallowed as a channel argument). This checks the real CLI's flag order.
- [ ] **12. (b) The `tg` badge.** Open the Agent Board. Expect `tg` on the Telegram lead's pane, with the tooltip "Telegram channel on (delivery not checked by the board)", and none on a teammate pane or a lead without a token. Check in the light theme and in the dark theme.
- [ ] **13. (c) `approve` on the folder-trust dialog.** Start `claude` in a directory it has not trusted yet (a fresh `mktemp -d` under a git init) in a scratch window; while the trust dialog shows, run `tmux-ctl approve <window> once`. Expect exit 1 with `approve: no permission prompt in <window>` and no key sent. Write down what it did if it differs: ______
- [ ] **14. Kill switch.** Restart the lead with `TC_TELEGRAM=0 claude-orchestrator --continue`. Expect no `--channels` in its `ps -o args=` line and no `tg` badge.
